# architecture.md

How the app is wired. Keep it this shape.

## Data flow in one picture

```
Visitor ──► app/page.js (server component)
                 │
                 └─► lib/products.js getProducts()
                          │
                          └─► MongoDB  collection: products

Owner ──► /admin/login ──► POST /api/admin/login ──► sets httpOnly cookie
      └─► /admin  (layout checks cookie, else redirect)
                 │
                 └─► fetch /api/products (POST / PUT / DELETE)
                          │
                          └─► lib/products.js ──► MongoDB
```

The public page never calls an API route. It reads the database on the server
and ships HTML. API routes exist only for the three admin mutations plus login
and logout.

## Database

One database, one collection. No relations, no second collection.

**Collection: `products`**

| Field | Type | Notes |
| --- | --- | --- |
| `_id` | ObjectId | generated by MongoDB |
| `name` | String | required, e.g. "Cortado" |
| `description` | String | one line, may be empty |
| `price` | Number | rupees, integer, e.g. `140` |
| `category` | String | one of: `Coffee`, `Tea`, `Pastries`, `Food` |
| `imageUrl` | String | pasted URL, may be empty |
| `isSpecial` | Boolean | shows the daily-special badge |
| `createdAt` | Date | set on insert |

Validate on the server inside the route handler, with plain `if` checks:
`name` non-empty, `price` a number `>= 0`, `category` in the allowed list.
Reject with `400` and a readable message. Do not add a validation library.

## `lib/mongodb.js`

The standard cached-client pattern so hot reload does not open a new connection
on every save:

```js
import { MongoClient } from 'mongodb'

const uri = process.env.MONGODB_URI
let client
let clientPromise

if (!global._mongoClientPromise) {
  client = new MongoClient(uri)
  global._mongoClientPromise = client.connect()
}
clientPromise = global._mongoClientPromise

export async function getDb() {
  const connected = await clientPromise
  return connected.db('cafe')
}
```

## `lib/products.js`

Four functions, each a few lines. They are the only place that touches the
collection.

- `getProducts()` — all items, sorted by `category` then `name`. Converts
  `_id` to a string before returning, so server components can pass plain
  objects to client components.
- `createProduct(data)`
- `updateProduct(id, data)`
- `deleteProduct(id)`

## `lib/auth.js`

```js
export const COOKIE_NAME = 'cafe_admin'

export async function isAdmin() {
  const store = await cookies()
  return store.get(COOKIE_NAME)?.value === process.env.ADMIN_PASSWORD
}
```

- `POST /api/admin/login` compares the submitted password to
  `process.env.ADMIN_PASSWORD`. On match, sets `COOKIE_NAME` with
  `httpOnly: true`, `sameSite: 'lax'`, `secure` in production, `maxAge` 7 days.
  On mismatch, returns `401`.
- `POST /api/admin/logout` clears the cookie.
- `app/admin/layout.js` calls `isAdmin()` and `redirect('/admin/login')` if false.
- **Every mutating route handler calls `isAdmin()` first** and returns `401`
  otherwise. The layout guard protects the UI; the route guard protects the data.

This is intentionally the simplest workable scheme. Note the trade-off in the
README: a single shared password with no hashing and no rate limiting is fine
for a coursework demo and would not be acceptable for a real shop.

## API contract

| Method | Path | Auth | Body | Returns |
| --- | --- | --- | --- | --- |
| GET | `/api/products` | none | — | `{ products: [...] }` |
| POST | `/api/products` | admin | product fields | `{ product }`, 201 |
| PUT | `/api/products/[id]` | admin | product fields | `{ product }` |
| DELETE | `/api/products/[id]` | admin | — | `{ ok: true }` |
| POST | `/api/admin/login` | none | `{ password }` | `{ ok: true }` or 401 |
| POST | `/api/admin/logout` | none | — | `{ ok: true }` |

Errors always return `{ error: "readable message" }` with a real status code.

After a successful mutation the admin page calls `router.refresh()` so the list
re-reads from the server. Do not keep a second copy of the menu in client state.

## `data/site.js`

Everything that is not a menu item lives here as one exported object, so there
is a single place to change the café's details.

```js
export const site = {
  name: 'Kettle & Crumb',
  tagline: 'Slow coffee and warm bread, since 2019.',
  address: '...',
  phone: '...',
  email: '...',
  mapsEmbedUrl: '...',
  mapsDirectionsUrl: '...',
  hours: [
    { day: 'Monday', open: '07:30', close: '19:00' },
    // ... Sunday, use `closed: true` for a closed day
  ],
  gallery: [{ src: '...', alt: '...' }],
  socials: [{ label: 'Instagram', href: '...' }],
}
```

`isOpenNow(hours)` in `lib/utils.js` returns `{ open: boolean, until: string }`
by comparing the current time against today's row. Keep it under 20 lines and
ignore timezones — the site serves one local café.

## Environment

`.env.local`, never committed. Ship a `.env.example` with the same keys and
empty values.

```
MONGODB_URI=
ADMIN_PASSWORD=
```

## Seeding

`scripts/seed.js` inserts about 12 items across the four categories with real
names, real descriptions and sensible rupee prices, then exits. Run with
`node scripts/seed.js`. It clears the collection first so it is safe to re-run.
